# run/4 修改与撤回约定

用户要求：从 2026-11-08 起，所有修改都要编写修改日志，支持后续随时撤回。

- 每次修改前，在 `change_backups/<唯一修改编号>/` 备份将受影响文件的原始内容，记录相对路径及 SHA-256。新增文件记录为新增，不伪造旧版本。
- 在 `CHANGELOG.md` 追加记录：修改编号、北京时间、目的、受影响文件、具体行为变化、验证结果、备份位置及撤回方法。包括代码、配置、测试和文档修改。
- 修改完成后记录受影响文件的最终 SHA-256，方便撤回时判断是否存在后续修改。
- 撤回前核对当前文件与该次修改后的版本是否一致；若存在后续修改，按修改块逆向处理，不整文件覆盖后续工作。删除新增文件也须确认没有后续改动。
- 撤回本身也追加日志并备份当前内容，不删除历史日志和旧备份。
- 备份源代码、测试及工程配置即可；构建产物通过重新编译恢复。若修改工程外共享文件，也须单独备份并明确记录。
- 不将某次修改前不存在的备份描述为可恢复旧版本；既往修改需依据日志和实际源码逆向撤回。
