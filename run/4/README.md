## 十字识别与补线

首次要求四角齐全，允许左右角点不同高。确认后保持通过状态，补线使用当前帧：
- 同侧上下角点齐全：连接两点，仅补缺口范围。
- 近端角点消失：从远端角点沿实测出口边界向上跟踪最多10行，至少4点，
  最小二乘拟合x(y)，再向下延伸。两侧独立，因此支持一侧连接、另一侧拟合。
- 横向斜率绝对值超过每行1像素时拒绝该侧结果，允许竖直边界（零斜率）。

实测边界、基础巡线算法与路宽模型不修改。重建边界保存到独立数组，最终中线
写入mid_line，img_line_valid=3；只有另一侧有实测或重建依据时才生成中线。
当前帧拟合不成立不复用旧路径；状态P=4提示依据不足，控制区域中线置无效。
本版本按远端角点持续可见的使用前提设计，没有历史路径保持分支。

控制区经历过半数行正常双边缺失后，才允许退出；从控制区首行到图像底部恢复
连续实测双边、路宽在入口参考宽度的0.5～1.5倍时退出。此检查在覆盖中线前执行。
这样不会在刚识别到远处十字、近处仍完整时立即退出。出口阈值需实车验证。

主循环顺序：基础巡线 → 十字识别/补线/退出 → 舵机更新 → 屏幕刷新。
屏幕蓝色为实测边界，绿色为重建边界；红色为双边或十字中线，黄色为普通单边中线。
角点候选黄色，四角确认绿色。X为当前帧四角确认值，不代表通过状态。
P：0普通、1双侧上下连接、2双侧出口拟合、3混合、4当前依据不足。
M为当前角点位掩码：1上左、2上右、4下左、8下右。V/S保留。

预筛和角点参数集中在CROSS_宏：全高度寻找中央连续宽白区（图宽75%、至少4行），
不等待近处丢边。目标在参考图二阶段确认，尚未用原始实拍帧或高速实车验证。

## 上角点关联修正

四角首次确认后，后续上角点优先匹配最后通过验证的同侧上角点。
当前初值：每帧横向变化不超过16像素、纵向不超过24像素；左右角点仍允许不同高。
上角点间距须在上一有效帧的75%～125%以内，且不小于首次确认间距的75%，
避免下角点消失后换到右侧窄结构，以及连续小幅收窄绕过单帧检查。
这些范围是待实车验证的参数，不代表高速可靠性已确认。

上角点成对验证在“四角不齐返回”之前执行。被拒绝的候选不更新关联参考、
不画作有效上角点、不生成绿色补线；P=4，控制区中线无效，全区无效时舵机保持
上一指令。下一帧仍根据最后一对有效上角点重新匹配，退出或尺寸变化时清空关联。
没有用历史坐标直接补线，拟合范围仍为10行。

新增回归复现旧版将出口错换成右侧约24像素窄通道的问题，并验证拒绝错点后重新
识别原出口、允许真实角点平移及左右不同高、退出后不沿用上一个十字的关联。

## 下角点出画后禁止重新接入

四角确认后左右下角点分别关联上一有效位置。当前初值：横移最多16像素，
向下移动最多24行，向上回退最多6行；候选还须满足同侧上下关系和连线斜率。
下角点进入底部16行区域后，首次失去相容观测就将该侧标记为已出画。
本次通过期间不再使用该侧新出现的下角点，仅使用远端边界拟合；左右独立切换。
尚未到近底部区域的短暂漏检不锁定出画，可以重新关联原下角点。
下一次四角确认时重新初始化两侧记录。拟合范围仍为10行。

回归测试包含下角点出画后假角点反复出现：原版中线94与104间跳变，
修改后保持远端拟合，不再切回错误上下连线。测试也覆盖单侧先出画、
早期漏检恢复及下一十字重新进入。帧间移动范围与近底部阈值仍需实车验证。

## 跟踪首次确认的上角点及路口边缘

四角首次确认时保存每个上角点外侧18列的上轮廓相对高度，作为本次路口的
边缘形状模板。后续候选除位置、宽度关联外，还须匹配这段外侧边缘：
至少6个可比较位置，至少75%位置相对高度误差不超过4像素。
坐标允许平移，左右角点不要求同高；模板整次通过保持不变，避免逐帧漂移到
上方弯道的另一个转折。下一个十字四角确认时重新采集模板。
这18列沿外侧横向路口边缘取样，不增加向上拟合行数（仍最多10行）。
匹配失败仍走P=4，不用旧坐标冒充当前角点，不强制补线。

新增ARM回归：真实右上角点移动时，上方10行另一个较近弯道转折会让旧代码
误选；新代码匹配原路口边缘，连续帧保持正确角点。该测试覆盖十字独立调用和
环岛集成调用。模板容差仍需实车验证，不能保证所有透视变化下都能匹配。
