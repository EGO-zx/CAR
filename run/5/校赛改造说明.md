# run/5：校赛版改造说明

资格赛代码（`run/4`）已经跑通并归档。校赛的赛道未知、只提前知道元素种类，
所以本版本的原则是：**删掉依赖固定里程/固定位置的功能，保留对所有赛道都成立的能力。**

---

## 一、改造思路

资格赛代码里有大量"按固定里程段收费"的策略：

- 直道加速：只在 90000~105000 计数区间提速
- 红砖避障：只在固定距离段左移中线
- 倒车：只在盲盒任务的距离点触发
- 三档速度：靠人工按键切换

这些策略的共同前提是**赛道形状和里程可预知**。校赛赛道未知，同样的里程在不同赛道上
对应完全不同的位置，所以整块删除，而不是调参数。

保留下来的都是"从图像本身出发"的能力：巡线、单边补偿、丢线自救、十字、环岛、斑马线。

## 四、新增改动

### 4.1 十字扫描降频（`img_process.c`）

**问题**：去掉"只处理两个十字"的限制后，`cross_detect()` 需要每帧对全图做预筛和角点扫描。
过了两个十字之后，这部分开销一直存在，主循环时间被挤占，弯道里表现为打角滞后、冲出赛道。

**改动**：

```c
#define CROSS_SCAN_PERIOD 2      /* 1 = 恢复每帧扫描 */
static uint8_t cross_scan_skip;

/* cross_process 内，只降低"扫图"的频率 */
if ((cross_scan_skip++ % CROSS_SCAN_PERIOD) == 0)
    cross_detect(image, rows, cols);
```

**关键点**：

- 只降频 `cross_detect`（预筛 + 角点扫描），**十字状态机仍每帧推进**
- 补线、状态转换、掩码更新都是每帧进行，响应速度基本不变
- 角点数据最多延迟 20ms（一帧）
- `cross_reset_counters()`（C15 复位）会把计数清零，复位后第一帧必定扫描

`CROSS_SCAN_PERIOD` 设 1 即可恢复原行为，便于对比。

## 八、已知问题与排查记录

### 8.1 弯道直冲（未解决，排查中）

现象：两侧边界都有、`R` 与 `P` 均为 0 时，舵机突然回正、直线冲出弯道。

已定位的可疑点排序：

1. **斑马线误判（最可能）**：`zebra_process()` 会把上下两个锚点直连成中线，
   并把整段标记为有效（`img_line_valid=4`）。弯道里出现横向黑色接缝（接缝、
   阴影、胶带）就可能触发 → 控制窗口被直线占满 → 舵机回正。
   判别方法：冲出瞬间看 `Z:` 是否变成 1/2、图像中线是否变绿。
2. **边界种子/斜率重置**：底部连续找不到白走廊时 `slope=0`，中线退化成竖直直线。
3. **丢线自救回中**：需连续 25 帧无有效中线，`V` 会先掉到很低，通常可排除。
4. **十字桥接**：会同时把 `P` 置非 0，可据此排除。

### 8.2 右侧环岛

`run/5` 只支持左侧环岛（判据写死"左边丢 + 右边直"）。右侧环岛的对称实现放在 `run/6`。

### 8.3 未验证项

- `STEER_GAIN=0.50` 是在低速下调通的，提速后需要重新确认
- 环岛判据的阈值（`S1_LOST_ROWS`、`S1_LINE_RESIDUAL` 等）需按实车摄像头高度标定

## 九、与 run/6 的关系

`run/5` 是**普适基线**，只做删减 + 十字降频，参数实车验证过。

`run/6` 是**新算法实验版**，在 `run/5` 基础上增加：

- 环岛判据左右对称（肩点识别、岛屿跟踪、出环补线三处都按方向分支）
- 丢线自救左右对称（按控制窗口内左右丢线行数决定搜索方向）
- 状态显示改为 `0` / `L1~L5` / `R1~R5`

底盘参数（速度、增益、十字降频）与 `run/5` 完全一致，便于对照。
